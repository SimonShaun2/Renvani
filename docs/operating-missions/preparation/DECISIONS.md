## Recording a decision

Each accepted decision must record the exact value/rule and version, scope and exclusions, supporting source/evidence, accountable decision-maker, date, affected method/mission/consumer, negative cases and invalidation behavior. Preserve earlier records as superseded rather than silently rewriting history. A test fixture may declare an example policy; that never approves a policy for a real tenant.

Open decisions block only the affected implementation or activation claim. Documentation, synthetic examples, unrelated accepted contracts and Part I work can continue. Current user authorization covers this preparation sequence; it does not record Part I release acceptance or activate mission runtime.
