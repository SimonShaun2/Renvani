## Method and limits

Page files were enumerated from the exact Git tree. URL patterns omit parenthesized route groups and preserve dynamic segments (including optional catch-alls); concrete slugs and IDs are not expanded. Principal UI imports, reachable hook/API modules and local imports were parsed with the TypeScript AST. Type-only imports were excluded. The table's data-module IDs resolve to the catalog below. A reachable module may export several functions; its endpoint expressions do not prove the page invokes every export. No network calls or customer actions were executed to build this inventory.

**State markers:** L = loading/pending source marker, E = error/unavailable marker, Z = empty-result marker. Each links to one concrete source location; the JSON records all selected locations. These indicators identify code to review, not comprehensive branch analysis, rendered-state acceptance or measured coverage. “No marker in scope” is not a claim that a state does not exist. Local boundary files and redirect/not-found actions are recorded separately.

**Roles:** table values describe source UI gates. [Middleware](https://github.com/SimonShaun2/Renvani/blob/b45b4996b64b16859e44a79b171b11cbe52c3e6a/apps/web/middleware.ts), [route policy](https://github.com/SimonShaun2/Renvani/blob/b45b4996b64b16859e44a79b171b11cbe52c3e6a/apps/web/src/lib/route-access.ts), [server session](https://github.com/SimonShaun2/Renvani/blob/b45b4996b64b16859e44a79b171b11cbe52c3e6a/apps/web/src/lib/server-session.ts) and [Clerk route decisions](https://github.com/SimonShaun2/Renvani/blob/b45b4996b64b16859e44a79b171b11cbe52c3e6a/apps/web/src/lib/clerk/route-decision.ts) remain distinct from backend authorization. App routes require a server session. Mobile middleware admits owner/admin/technician by prefix, but the [mobile layout](https://github.com/SimonShaun2/Renvani/blob/b45b4996b64b16859e44a79b171b11cbe52c3e6a/apps/web/app/%28mobile%29/layout.tsx) narrows the actual page to **owner or technician**. Do not infer admin mobile access from the prefix map alone. Import/reporting pages add owner/admin server guards. Automation, payment settings and home-service settings have separate owner/admin edit controls; client UI controls do not establish server enforcement.

**API role differences to exercise, not erase:** `/command-center` is admitted for dispatcher by UI prefix policy, while the [brief endpoint](https://github.com/SimonShaun2/Renvani/blob/b45b4996b64b16859e44a79b171b11cbe52c3e6a/apps/api/src/routes/command-center/index.ts#L9) is owner/admin only. The UI allows the distinct `office` role on estimates, while [estimate route policy](https://github.com/SimonShaun2/Renvani/blob/b45b4996b64b16859e44a79b171b11cbe52c3e6a/apps/api/src/routes/estimates/index.ts#L48) and [revenue-inquiry policy](https://github.com/SimonShaun2/Renvani/blob/b45b4996b64b16859e44a79b171b11cbe52c3e6a/apps/api/src/routes/revenue-inquiries/index.ts#L17) name owner/admin/dispatcher (selected estimate reads additionally name technician), not office. These source differences need role-specific acceptance and product/security disposition; a navigation link is not evidence of authorized API access. See the [six-group backend map](BACKEND-INVENTORY.md) and [operator packet](OPERATOR-ACCEPTANCE.md).
