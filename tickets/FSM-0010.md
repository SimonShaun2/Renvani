## Objective

Inventory the actual repository CI configuration, build/test commands, environments, branch protections, secrets and rollback capability. Specify an enforceable **batch CI** plan for the agent-first FSM build. The full suite remains a later offering. Do not implement a per-commit or per-PR trigger.

## Deliverables

1. Verifiable inventory of workflows or their absence, clean-clone build/test baseline, environment state and whether anything serves traffic. Record exact SHA, commands, output and source paths.
2. Batch registry contract: approved batch ID, member tickets/PRs and exact heads, base ancestry, one authorized run, expected commands, runtime and cost limit, owner, result URL, failure handling and invalidation on head change.
3. Gate implementation plan: CI status publisher with narrow authority, peer review/QA/Security exact-head inputs, **`dev`** branch protection/required checks, founder-only approval for each named PR and exact reviewed head, no comment-only substitute for technical gates, fail-closed behavior. Codex Lead / Technical Lead and Platform coordinate approved batches; E.. CoS advice is optional and never a gate, per [founder directive #420](https://github.com/SimonShaun2/Renvani/issues/420).
4. Local test matrix and CI suite selection for schema, tenant isolation, consent, agent authority, migration replay, integration, E2E, accessibility and security according to risk. No live vendor calls or production credentials.
5. Integration branch protection and release promotion proposal, with rollback and observability. Main remains founder-controlled production promotion.
6. Migration plan for PR #1 and old FSM-NNNN issue mappings to the FS board, without silently auto-merging.
