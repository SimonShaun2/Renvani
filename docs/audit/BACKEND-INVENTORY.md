## Common authentication and authorization boundaries

The [authenticate plugin](https://github.com/SimonShaun2/Renvani/blob/b45b4996b64b16859e44a79b171b11cbe52c3e6a/apps/api/src/plugins/authenticate.ts) verifies a bearer token, resolves the current user/company and checks membership. Its JWT path checks active user and company membership; its Clerk path resolves organization and staff membership server-side. The role used by [requireRole](https://github.com/SimonShaun2/Renvani/blob/b45b4996b64b16859e44a79b171b11cbe52c3e6a/apps/api/src/lib/authorize.ts) comes from request.user, not the submitted body. The global company-scoped-write plugin provides an optional transaction helper; its presence is not proof that every route uses a tenant session or RLS.

| Code | Observed route policy |
|---|---|
| P | Public, no staff authentication. Public slug resolves the company; endpoint-specific rate limits and input boundaries apply. |
| O3 | Authenticated owner/admin/dispatcher. The distinct `office` role is not included. |
| E4 | Authenticated owner/admin/dispatcher/technician; technician estimate reads require the service’s assigned-job access check. |
| JA | Authentication present; no explicit role allowlist at that route. List/read/complete handlers have additional technician checks as identified below. |
| JR / JW | Authentication plus technicianOwnJob, using 404 for unassigned reads / 403 for unassigned writes. Other-tenant jobs are not resolved by the scoped lookup. |
| JS | Authentication plus denyTechnician, which allows owner/admin/dispatcher/office. |
| JP | Explicit five-role allowlist plus technician assigned-job read guard. |
| M5 | Five-role allowlist. Services enforce tenant and technician assignment; non-technicians must supply a technicianId for `/mobile/today`. |
| CA | Owner/admin only; onRequest auth/role gates run before query validation. |

Jobs and technician restrictions are grounded in [technician-scope.ts](https://github.com/SimonShaun2/Renvani/blob/b45b4996b64b16859e44a79b171b11cbe52c3e6a/apps/api/src/lib/technician-scope.ts). `listJobsHandler` replaces a technician’s requested technicianId with their own linked record; `getJobHandler`, complete-job and complete-task handlers enforce assignment. `createJobHandler` is authentication-only at the route and its service accepts company/actor inputs; this is not labeled office-only. The matrix preserves these differences for product/security acceptance.
