## Scope, traceability and evidence rules

This is the bounded queue/outbound slice of [legacy #7 / FSM-0006](https://github.com/SimonShaun2/Renvani/issues/7), authorized by [build specification 8](https://app.notion.com/p/40f317b92d158157997dcb3a1266058e). It reuses [FS-81 retry, dead-letter and replay contract](https://github.com/SimonShaun2/Renvani/blob/b45b4996b64b16859e44a79b171b11cbe52c3e6a/docs/contracts/fs-81-queue-retry-dead-letter-v0.1.md). The FS-81 document retains its historical PROPOSED header; the mechanisms cited below are present in this pinned source. This report does not approve that contract, close the full legacy integration inventory or revive historical Sprint 0 gates.

**Source observed** means code was inspected. **Test exists** means a related file was located, without claiming every scenario is covered. **Runtime verified** is false throughout. No worker was started; no queue job, database migration, replay, HTTP webhook, provider call or customer message was executed. Source assertions and document reference checks are the only checks run for this deliverable.

The outbound subset is the complete notifications dispatcher plus its observed API/worker/Stripe producers, the API SMS/email provider seams, shared comms policies and inbound Twilio STOP path. Synchronous emails outside that dispatcher and unrelated integration internals are not an exhaustive scope claim. The [JSON source appendix](worker-queue-inventory.json) preserves all 52 direct `<queue>Queue.add` calls, payload/options expressions, exact source positions, queue bindings and the 16 outbound entries. It excludes test mocks and does not claim arbitrary aliases or indirect `queue.add` calls are fully resolved.

## Current inbound Twilio behavior and proposed consent work

The [webhook app](https://github.com/SimonShaun2/Renvani/blob/b45b4996b64b16859e44a79b171b11cbe52c3e6a/apps/webhook/src/app.ts) registers POST `/twilio` with [signature verification](https://github.com/SimonShaun2/Renvani/blob/b45b4996b64b16859e44a79b171b11cbe52c3e6a/apps/webhook/src/middleware/twilio-verify.ts). Missing configured token returns 503; absent/invalid signature returns 403. Verification signs the request URL plus sorted form parameters and uses constant-time digest comparison after length checking. Correct external URL/proxy configuration is an operational prerequisite, not runtime-tested here.

At the dev SHA, [Twilio handler](https://github.com/SimonShaun2/Renvani/blob/b45b4996b64b16859e44a79b171b11cbe52c3e6a/apps/webhook/src/handlers/twilio.handler.ts) recognizes the trimmed, uppercased exact STOP word. With a shared sending number, it withdraws contact permission from matching live customer phone rows across their own tenants, with each update scoped to that row’s company. The query is capped at 500 rows. Other replies use recent outbound SMS history to choose one unambiguous company, then resolve a customer within that company. Unknown/ambiguous routing returns an empty success response without a tenant write. MessageSid is recorded but no explicit replay-dedupe guard was observed in this handler. This is a source map, not proof of carrier opt-out state, concurrent send cancellation or a general inbound idempotency guarantee.
