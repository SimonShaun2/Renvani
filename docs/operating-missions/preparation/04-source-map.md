## Read and commit boundaries

1. Derive company and actor from the authenticated server context or independently verified provider/site binding. A valid UUID or queue envelope does not prove ownership.
2. Assemble planning facts using named existing services. Store field-specific source references, source versions, timestamps, covered ranges and completeness. Do not copy entire customer histories into model context.
3. The proposed fifteen-minute cache is a ceiling where valid, not permission to use stale scheduling, balance, stock, consent or grant data.
4. At dispatch/commit, recheck current authorization and authoritative mutable facts. Actual lock/version/transaction semantics are Codex implementation work in OM-02/03/05.
5. Domain booking and inventory services own reservations. An OM resource record must refer to those constraints, including manual and customer self-service consumers.
6. Existing source attribution sanitizes a specific whitelist. New provider/click IDs need an explicit compatible contract and permitted-use decision; arbitrary raw URLs or customer text cannot be slipped into attribution.
7. Keep legacy report definitions and historical observations intact. Add a versioned OM projection with the [metric definitions](03-metrics-and-accounting.md), not stronger labels on existing fallback totals.
